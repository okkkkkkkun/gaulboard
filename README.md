# ガウルボード

サンフレッチェ広島の試合が終わったあとに、メモと配置を一枚の戦術カードへ落とすためのアプリです。スマホでもデスクトップでも、その日のうちに書けて、あとから見返せます。

クラブ公式のツールではありません。個人のアーカイブです。

## できること

- 日付、対戦相手、ホーム／アウェイ、大会、スコア、試合後メモを書く
- フォーメーションを選んで、ピッチ上の選手をドラッグし、名前と背番号を付ける
- プレス（金色）と動き（白）の矢印を引く
- プレッシング、ビルドアップ、キーモーメント、良かった点、課題、マン・オブ・ザ・マッチ、評価を手で書く
- カードを一枚のレイアウトで見て、PNG として保存する
- 対戦相手と大会で過去のカードを探す。カードは端末の中に残り、JSON で別の端末へ移せる
- 任意で、メモから戦術欄の下書きを作る
- 任意で、カードを Notion のデータベースへ送る

API キーがなくても、作成から PNG 保存までの流れは全部動きます。

## スタック

Next.js 15（App Router）、React 19、TypeScript、Tailwind CSS 4、shadcn/ui、IndexedDB（Dexie）、Zod、Vitest。PNG はブラウザ側の `html-to-image` です。ホーム画面に追加できる PWA で、サービスワーカーがアプリの殻をキャッシュします。

## なぜ端末の中に置くか

カードは見ている人のメモなので、サーバーにデータベースを置かず、ブラウザの IndexedDB に残します。作成、編集、アーカイブ、検索はオフラインでも動きます。Vercel のようなサーバーレス環境でも、ネイティブモジュールなしでビルドできます。

端末をまたぐときは、アーカイブの「JSONを書き出す」でバックアップを作り、別の端末の「JSONを読み込む」で置き換えます。共有シートが出るブラウザでは、ファイルアプリや別の端末へ直接渡せます。

そのブラウザで最初に開いたときだけ、2026年11月8日のアウェイ・FC町田ゼルビア戦（0-0、明治安田J1リーグ）をサンプルとして1件入れます。公開されている結果と並びをもとにしたファンのメモで、公式の戦評の転載ではありません。編集しても削除しても構いません。一度でも開いたあとに全部消しても、サンプルは戻りません。

## Vercel に置く

1. GitHub などにこのリポジトリを置き、Vercel で Import します。フレームワークは Next.js のままです。
2. ビルドコマンドは `next build`、出力は Vercel の標準のままで足ります。環境変数がなくてもデプロイできます。
3. AI 下書きや Notion を使うときだけ、Project Settings → Environment Variables に `OPENAI_API_KEY`、必要なら `OPENAI_BASE_URL` と `OPENAI_MODEL`、Notion なら `NOTION_API_TOKEN` と `NOTION_DATABASE_ID` を入れます。カードの本文はブラウザから API に送られ、キーはサーバーに残ります。
4. デプロイした HTTPS の URL をスマホで開きます。

## ホーム画面に追加する

iPhone（Safari）: 共有ボタンから「ホーム画面に追加」。名前はガウルボード、アイコンは紫の三本矢です。追加したあとは Safari の枠なしで開きます。

Android（Chrome）: メニューの「アプリをインストール」または「ホーム画面に追加」。通信がないときも、一度開いたアーカイブと新規作成のページは開けます。まだ開いていない試合ページは、オフライン用の案内になります。

## 必要環境

- Node.js 22 以降
- npm

## 起動

```bash
npm install
cp .env.example .env.local   # キーを使うときだけ
npm run dev
```

ブラウザで <http://127.0.0.1:47231> を開きます。

```bash
npm test          # カードのロジック、保存、AI応答の解釈、Notion の形
npm run lint
npm run build
npm start         # 本番モード。ポートは同じく 47231
```

## 環境変数

すべて任意です。未設定のボタンは、理由を書いたうえで押せない状態になります。

| 変数 | 役割 |
| --- | --- |
| `OPENAI_API_KEY` | あるときだけ「メモから下書き」が有効 |
| `OPENAI_BASE_URL` | 既定は `https://api.openai.com/v1`。OpenAI 互換のエンドポイントに差し替え可 |
| `OPENAI_MODEL` | 既定は `gpt-4o-mini` |
| `NOTION_API_TOKEN` | Notion インテグレーションのトークン |
| `NOTION_DATABASE_ID` | 書き出し先データベースの ID |

キーはサーバーだけで読みます。`NEXT_PUBLIC_` にはしません。ブラウザのコードに埋め込みません。

AI は、メモにない事実を創作しないよう指示したうえで JSON を受け取ります。返ってきた文は下書きです。戦術欄にすでに文字があるときは、置き換える前に確認します。フォーメーションは既定の形（3-4-2-1、4-4-2、3-5-2、4-2-3-1、4-3-3、4-1-4-1）として読めたときだけ配置を動かします。選手の名前は残します。

## Notion に期待するデータベース

インテグレーションを、そのデータベースに接続してください。プロパティ名は次のとおり、完全一致です。大会と会場はセレクトにしていません。候補にない文字列で書き出しが失敗しないように、テキストです。

| プロパティ | 型 | 入るもの |
| --- | --- | --- |
| 試合 | タイトル | `2026-11-08 FC町田ゼルビア` のような見出し |
| 日付 | 日付 | 試合日 |
| 対戦相手 | テキスト | 相手クラブ名 |
| 大会 | テキスト | 大会名 |
| 会場 | テキスト | `ホーム` または `アウェイ` |
| スコア | テキスト | 会場順。例: `FC町田ゼルビア 0-0 広島` |
| フォーメーション | テキスト | カードに書いた並び |
| プレッシング | テキスト | プレッシングの狙い |
| ビルドアップ | テキスト | ビルドアップの形 |
| キーモーメント | テキスト | 試合の要点 |
| 良かった点 | テキスト | 保てたこと |
| 課題 | テキスト | 次に直すこと |
| MOM | テキスト | マン・オブ・ザ・マッチ |
| 評価 | 数値 | 0 から 10。未評価なら空 |
| メモ | テキスト | 試合後メモの先頭（約1900字まで） |
| 配置 | テキスト | 選手名と矢印の種類 |

ページ本文にも、メモ、プレッシング、ビルドアップ、配置を置きます。長い文章は Notion のテキスト上限に合わせて切れます。

## カードの見方

スコアの入力はいつも「広島の得点 / 相手の得点」です。ホームなら広島が左、アウェイなら相手が左、という並びはカード側で入れ替わります。評価は 0 から 10 の 0.5 刻みです。空のままにもできます。

ピッチは上が相手ゴール、下が広島ゴールです。配置モードで選手をドラッグし、矢印モードでドラッグして線を引きます。矢印は 16 本までです。

## これから

次に足すなら、前後半で配置を切り替えること、曲線の動き、交代の時刻、試合どうしの並べ見です。端末をまたぐコピーは、いまは JSON の書き出しと読み込みで足しています。
